## 규칙

1. 실제 자료로 잠금 시험집합을 돌리는 것은 **한 번**이다.
2. 임계값·사건 정의·채널 집합은 검증집합까지만 보고 정한다.
3. 시험 결과를 보고 설정을 바꾸면, 바꾼 사실과 이전 결과를 둘 다 남긴다.
4. 합성 자료 결과는 어떤 표에도 넣지 않는다.

## 2026-10-27 run1 이후 수정 (시험 결과를 본 뒤의 변경)

run1 결과를 본 뒤 고친 것. run1 수치는 그대로 둔다. 고친 이유는 구현 문제다.

| 문제 (run1 에서 확인) | 수정 |
|---|---|
| 임계값 후보가 0.05~0.95 뿐이라 0.95 에 걸려 멈춤 (30·60분 모두 0.950) | 로짓 공간 81점, 약 6e-6 ~ 0.9997 |
| 검증 구간(2020–2022, 극소기) 사건 7건으로 임계값 선택 | 학습 구간 4분할 교차검증 예측 + 검증 구간 예측, 사건 약 47건으로 선택. 시험 구간은 쓰지 않음 |
| 목표 오경보비를 못 맞추면 오경보비 최소값을 고름 (탐지율 무시) | 1) 오경보비 ≤35% 중 탐지율 최대 2) 없으면 탐지율 ≥70% 중 오경보비 최소 3) 없으면 CSI 최대 |
| 양성 가중치 약 3,400배로 확률이 0.95 이상에 몰림, Brier 기술점수 −31.9 | 가중치 sqrt(음성/양성), 선택 집합 예측으로 Platt 보정 |
| 검증 손실이 크게 흔들리다 7 epoch 에서 조기 종료 | 학습률 0.002 → 0.001, 인내 3 → 5, 최대 25 epoch |
| 오경보비 88% 인데 판정이 "최소 성공" | 오경보·선행 조건을 못 맞추면 "최소 성공 (탐지율 기준)" 으로 표시 |
| 분할 끝 날짜를 자정으로 읽어 2022-12-31 이 시험에 들어감 | 날짜만 주면 그날 전체 포함 (run1 이전, 같은 날 수정) |

바꾸지 않은 것: 사건 정의, 분할 기간, 입력 채널, 모델 구조·예산, 목표 수치,
규칙 게이트 설계값(양성자 ≥1 pfu). 양성자 '배경 대비 3배' 조건은 표 1 에 비교
행으로만 넣었고, 설계값으로 쓸지는 팀이 학습·검증 구간 결과로 정한다.

## 2026-10-28 run3 이후 - 개발 모드 도입과 TCN 학습 수정

잠금 시험집합을 세 번 평가했다. 이후 설정 비교는 `--dev` (2010–2022 교차검증
예측만, 시험집합은 계산하지 않음) 로만 하고, 시험은 최종 설정에서 한 번만 돌린다.

run3 에서 확인한 학습 쪽 문제:

| 문제 | 수정 |
|---|---|
| 검증 손실이 epoch 마다 0.02~0.14 로 튀어 "가장 좋은 epoch" 가 우연에 좌우됨 (run3 은 3 epoch) | 12 epoch 고정 + 가중치 지수이동평균(0.999) + 코사인 학습률 |
| 15분 간격 솎기로 사건 직전 창(양성)도 3분의 1 로 줄어듦 | 음성만 솎고 양성은 전부 남김 |
| 교차검증 모델 4개의 출력 눈금이 달라 합친 점수에 임계값 하나를 쓸 수 없음 | 블록마다 따로 보정(Platt) 후 합침. 최종 모델은 블록 보정 계수의 평균 |

개발 모드 기준선 (logreg, 2010–2022 교차검증, 사건 47건): 탐지율 72%, 오경보 70%.
TCN 은 이 값을 기준으로 비교한다.

### dev1 (2026-10-28, 개발 모드, 시험집합 미계산)

TCN 12 epoch 고정: 30분 출력은 탐지율 70% 에서 오경보 96%, 60분 출력은 탐지율 72% 에서
오경보 70%. logreg 30분은 탐지율 70% 에서 오경보 70%. 학습 손실이 0.046 → 0.002 로
계속 떨어져 과적합으로 판단. 같은 학습에서 epoch 2·3·4·6·8·12 의 중간 가중치를
함께 평가하도록 개발 모드를 고쳤다. 결과는 `outputs/dev1_20261028/`.

### dev2 (2026-10-29, 개발 모드)

같은 학습의 epoch 별 결과 (탐지율 70% 에서 오경보, 30분 출력): 2 epoch 83%, 3 88%,
4 85%, 6 90%, 8 92%, 12 96%. epoch 가 늘수록 나빠져 과적합으로 확인. 가장 좋은
2 epoch 도 logreg(70%)보다 높다. 60분 출력은 66~70% 로 logreg 30분과 비슷하다.

다음 시도 (dev3): 드롭아웃 0.2 → 0.3, 가중치 감쇠 1e-4 → 1e-2, 3 epoch 고정,
30분 출력 학습 목표에 30~60분 앞 창을 0.5 로 (부드러운 라벨, 평가는 원래 라벨),
epoch 별 비교가 그 epoch 에서 멈춘 것과 같도록 학습률 감소를 끔.
결과 `outputs/dev2_20261028/`.

### dev3 (2026-10-29, 개발 모드)

규제 강화 + 부드러운 라벨 + 3 epoch. 30분 출력, 탐지율 70% 에서 오경보:
1 epoch 82%, 2 76%, 3 78%, 4 78%, 6 83% (dev2 의 96% 에서 크게 줄었다). logreg 70%.
블록별로는 2019-10~2022-12 (신세대, 사건 7건) 에서 TCN 탐지율 71% / 오경보 33%,
logreg 57% / 68%. 다른 블록에서는 logreg 가 낫거나 비슷하다.

epoch 2(76%)와 3(78%)의 차이는 사건 47건에서 잡음 수준이라 미리 정한 3 epoch 를
그대로 둔다. 이 설정을 최종으로 잠그고 시험집합은 한 번만 평가한다 (run4).
결과 `outputs/dev3_20261029/`.

### run4 (2026-10-29, 최종)

dev3 설정 그대로 시험집합 1회 평가. 이후 설정을 바꾸면 run5 로 적는다.
